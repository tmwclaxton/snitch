## Facts in PHP, narrative from the LLM
`DailyBriefFactsBuilder` computes followers, posts, times-usual, views-vs-usual for hidden-like Reels, format mix, best times, unused weekly ideas, ads, and sync health. Times-usual uses the same baseline as the dashboard (`DashboardMath::performanceIndex`: up to `PI_PRIOR_WINDOW` earlier posts, full loaded history, no 44-day cutoff). `prior_n` / `times_usual_early` are included so copy can avoid standout language on thin baselines; the numeric still matches the dashboard whenever PI is computable (>= 3 priors). Each account also gets `cadence` (posts in the last 7 days, days since last post, distinct posting days, `posted_every_day_last_7` for 7/7 London days, `posted_almost_daily_last_7` for 6+) plus `best_post_7d`. Root facts include `top_competitor_hit_7d` (posts inside the 7-day window only) and `cadence_gaps` (`own_is_longest`, `longest_handle`). Brand `own_handles` always join `allowed_handles` even when there is no `is_own_account` tracker. Never let the LLM invent numbers. Scene-description hooks fall back to the caption opening line. Best-time slots with fewer than 3 posts are labelled "early signal". Missing day-on-day followers say "Daily tracking starts today". Empty ads stay visible as "No ads found". Quiet or empty competitors go under Things to watch, not as moves. `sync_failed` is not quiet and not empty: say the refresh failed. `sync_empty` is only a successful empty scrape with no stored posts. The "Competitor posts in the last day" tile uses `format_mix.competitor_posts_24h` and a note listing every competitor post in `posts_last_24h` (for example `@great.friendship Reel 2.2x, @goodgym Reel 1.3x`). If there are none, the note is "none in the last day". Hidden-like views use `N times their usual views` in prose labels (never `N views vs usual`, and never mix views/likes labels). Engagement multipliers stay `N times their usual`. Do not use `top_competitor_hit` / 30-day `standout_winners` as that last-day note, or as a "best this week" figure.

`DailyBriefValidator` checks handles, post ids, numbers, 3-5 actions, no ellipsis, hook word cap, and cadence claims. Brand / own handles (`facts.brand.own_handles`, `facts.own.handle`) are always allowed. Numbers in prose that match facts (followers, deltas, counts) are allowed, including a trailing sentence period (`97.` = `97`). Counts `0` and `1` are always allowed (never treat as invented). Accounts with no posts / `sync_empty` are excluded from `cadence_gaps` (no 999-day sentinel); do not use them for longest-gap claims. Never mention internal post ids in copy (`post 218`, `post #218`, `post_id 218`, `(post_id 218)`, `(id 218)`); rewrite those to `their '{first 5 hook words}' {format}` (for example their 'Living Room Listens' Reel). Drop a parenthetical id when the phrase already names the post (`their Reel (post_id 218)`). Never stack `their their` or `Reel ... Reel`. Strip leftover empty brackets, and keep the id only in `related_post_ids`. Reject leftover internal-id phrasing. On Stories, call Instagram's sticker the "link sticker" (never "link in bio sticker"); rewrite `link in bio sticker` to `link sticker` case-insensitively. "Link in bio" stays valid for posts and Reels. Never borrow named people from competitor captions (`facts.borrowed_competitor_names`); rewrite to "a member's story" / "a member" only for plausible person names harvested from person-name patterns (not ordinary capitalised words), with case-sensitive whole-word rewrites, then reject leftovers. Soften standout / hit / top / outperformed wording when times-usual or views-vs-usual is at or below 1.2 (rewrite first; reject only if praise still remains); "best" may also refer to that handle's genuine in-window best. Reject "posts daily" / "every day" unless `posted_every_day_last_7`. Reject "almost daily" / "nearly daily" / "near-daily" / "daily-like" / "almost every day" / "posts most days" unless `posted_almost_daily_last_7` or at least 5 posts in the last 7 days (`posts_last_7d` / `posts_last_7d_count`). Scan headline, own_summary, competitor_summary, trends, watch, and action title/why/how/hook. Rewrite unsupported cadence adjectives first (daily-like → recent, almost daily → regularly, posts daily → posts) so a good brief is not discarded; reject leftovers so the LLM retries. When any tracker is `sync_empty`, rewrite longest-gap "among all tracked accounts" to "among accounts with posts". Reject follower "last 7 days" / "this week" wording unless `followers_change_7d.from_date` is exactly 7 days before `brief_date`; use the change `label` instead. Reject "best post this week / last 7 days" figures that are not on that named handle's `posts_last_7d` / `posts_last_24h` / `posts_yesterday` / `best_post_7d` / `top_competitor_hit_7d` / `top_competitor_hit_24h`. Rewrite first: swap the figure to that handle's in-window best, accept 1-decimal rounding (2.25 cited as 2.3), or soften "this week" to "recently"; reject only if the claim still cannot be grounded. Any `N times (their|your) usual` / `N.Nx` claim that names a competitor by `@handle`, handle token, `display_name`, or handle-derived brand phrase (for example "One House Social Club" / "Great Friendship") must match that handle's post multipliers in facts (7d, standouts, tops) within rounding - never borrow another handle's multiplier. When a format word (Reel / Carousel / Image) sits next to the figure, that post format must carry the figure; rewrite format or figure first. Distinctive hook/caption phrases must stay with their own post's multiplier and format. "Leads with N posts this week" must match `posts_last_7d_count` and the true weekly leader. Dates next to "posted" must be `posted_at` / `posted_label`, not event dates from captions. Drop Nx claims when a named account has no usable `times_usual` / `views_vs_usual`. Rewrite "reply to someone else's comment" on competitor posts to "comment on the post". Rewrite the figure to that handle's best known multiplier first; reject leftovers so the LLM retries. Standout / hit praise tied to "this week" must use an in-window post above the standout threshold; soften week wording for 14/30-day `standout_winners` rather than calling them this week's standout. Reject "longest gap" claims unless `cadence_gaps.own_is_longest`. Each model HTTP call retries on 429 / 5xx (`snitch.daily_brief.llm_tries`, default 4) with backoff and honours `Retry-After` (capped). Retry the LLM once with the violations listed. If still invalid or the model call fails, drop bad actions, clear invalid prose, and fill with deterministic fallback unless a ready LLM brief already exists for that date: never replace that row with fallback, keep it, log per-attempt `diagnostics`, and run `DailyBriefCopySanitizer` on the kept payload (post-id rewrite, conservative borrowed names, standout soften, `unused_weekly_ideas`). Do not run copy sanitizers on display (`DailyBriefPresenter`) or when returning an existing ready brief without regenerating. Ops: `snitch:generate-daily-briefs --sanitize [--user=] [--date=]` re-sanitises the stored daily payload and weekly idea rows in place. Ops: `--fallback` skips the LLM, implies force, and overwrites a ready LLM brief with the checked deterministic template (deploy `[regen-brief-user-1]` uses this). Fallback copy pluralises counts (`1 time`, not `1 times`). It may call a post a hit or use it as Reel inspiration only when times-usual / views-vs-usual is greater than 1.0; otherwise pick the best in-window format or omit. Template headline, summaries, and suggestions must take format, date, and multiplier from one post object; never mix a Carousel date with a Reel Nx. Run deterministic fallback through the same claim checker as LLM output (`checkedNarrative` / `validate`), then `rebindTemplateCitation` so claim rewrites cannot split format/date/Nx across posts. Never suggest replying to comments on a post with `comments` 0 - rewrite to comment on the post. Store `llm_attempts` and diagnostics on the payload. `snitch:generate-daily-briefs` also persists the current-month stored monthly report after briefs so PDF / share / audit do not keep a stale stored payload.
